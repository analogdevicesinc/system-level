ZCU102 Quick start
===============================================================================

This guide provides quick instructions on how to set up the
ADAR3000/3001-EVALZ on:

- :xilinx:`ZCU102` on FMC HPC1, through the SDP-I-FMC interposer

.. image:: ../../images/zcu102.jpg
   :width: 800

Using Linux as software
-------------------------------------------------------------------------------

Necessary files
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. important::

   Pre-built files for this reference design are not yet available on the
   Kuiper SD card image. Build them from source, as described below.

The following files are needed for the system to boot, in the root directory
of the BOOT partition of the SD card:

- HDL boot image: ``BOOT.BIN``, built from the
  :git-hdl:`projects/adar3000/zcu102` HDL project
- Linux kernel image: ``Image``
- Linux device tree: ``system.dtb``, built from
  :git-linux:`adi-adar3000-evb.dts <main:arch/arm64/boot/dts/xilinx/adi-adar3000-evb.dts>`

Instructions on how to build them from source can be found here:

- :ref:`linux-kernel zynqmp`. The ``adi_zynqmp_defconfig`` configuration
  enables the ADAR3000 driver. Build the device tree with
  ``make xilinx/adi-adar3000-evb.dtb`` and copy it to the SD card as
  ``system.dtb``.
- :external+hdl:ref:`adar3000`. More HDL build details at
  :external+hdl:ref:`build_hdl`.

Required software
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- SD card 16 GB imaged with :external+kuiper:doc:`Kuiper <index>`
- A UART terminal (PuTTY/Tera Term/Minicom, etc.), baud rate 115200 (8N1)

Required hardware
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- AMD Xilinx :xilinx:`ZCU102` FPGA board and its power supply
- ADAR3000/3001-EVALZ evaluation board
- SDP-I-FMC interposer
- Two bench power supplies, see
  :ref:`eval-adar3000 user-guide power-supply`
- SD card with at least 16 GB of memory
- Micro-USB cable, for UART
- LAN cable (Ethernet), optional, for remote access

More details as to why you need these, can be found at
:ref:`eval-adar3000 prerequisites`.

Testing
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Creating the setup
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

.. figure:: ../images/adar3000_zcu102_setup.jpg
   :alt: ZCU102 with the SDP-I-FMC interposer and the evaluation board
   :width: 900

   ZCU102 with the SDP-I-FMC interposer on FMC HPC1 and the ADAR3000/3001-EVALZ

.. esd-warning::

Follow the steps in this order, to avoid damaging the components:

#. Get the :xilinx:`ZCU102`.
#. Insert the SD card into the SD card slot of the FPGA board.
#. Configure the :xilinx:`ZCU102` for SD boot mode (mode switch SW6[4:1] in
   the position **4-OFF, 3-OFF, 2-OFF, 1-ON**).

   .. image:: ../../images/zcu102_1p0_bootmode.jpg
      :alt: ZCU102 boot mode switch set for SD boot
      :width: 400

#. On the ADAR3000/3001-EVALZ, fit the jumpers on P8 and P9, leave P4 as
   shipped (pin 1 to pin 2), and make sure P2, P12 and P13 are open, see
   :ref:`eval-adar3000 user-guide hardware-configuration`.
#. Connect the SDP-I-FMC interposer to the FPGA carrier FMC **HPC1** socket
   (J4), and the ADAR3000/3001-EVALZ to the interposer's 120-pin SDP
   connector, P5.
#. Connect the bench supplies to the evaluation board test loops, with the
   outputs off, as described in :ref:`eval-adar3000 user-guide power-supply`.
#. Connect USB UART (Micro-USB) to your host PC (J83).
#. Optionally, plug an Ethernet cable from your router or switch into the
   Ethernet port of the FPGA board.
#. Plug the power supply into the 12 V power input connector (J52).
#. Turn on the bench supplies, then the power switch on the FPGA board. The
   driver checks for the device while Linux boots, so the evaluation board
   must be powered first.
#. Make sure the FMC ``VADJ`` rail is at 1.8 V, see
   :ref:`eval-adar3000 user-guide vadj`.
#. Observe the kernel and serial console messages on your terminal (use the
   first ttyUSB or COM port the ZCU102 registers).

Checking the device
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The commands below are run on the FPGA board, in the serial terminal or over
SSH. The driver registers one IIO device, ``adar3000_0``, and prints nothing
in the kernel log when it finds the device:

.. code-block:: bash

   dmesg | grep -i adar
   grep . /sys/bus/iio/devices/iio:device*/name
   iio_info | grep -A1 adar3000_0

Expected output:

.. code-block:: bash

   /sys/bus/iio/devices/iio:device0/name:xilinx-ams
   /sys/bus/iio/devices/iio:device1/name:adar3000_0
   	iio:device1: adar3000_0 (buffer capable)
   		33 channels found:

If ``dmesg`` shows ``Failed to read/write scratchpad``, the device did not
answer: check that the evaluation board is powered and that ``VADJ`` is at
1.8 V, then reboot.

The device has 32 output channels, ``phase0`` to ``phase15`` for the delay
and ``power0`` to ``power15`` for the attenuation of the 16 elements, and one
input channel, ``temp16``. Elements 0 to 3 belong to beam 0, 4 to 7 to beam 1,
8 to 11 to beam 2 and 12 to 15 to beam 3.

Testing the driver
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The expected outputs below are those of a freshly booted board; run the steps
in order, since some of them build on the state left by earlier ones. A write
with ``iio_attr`` prints the value read back after the write.

**1. Temperature**

.. code-block:: bash

   raw=$(iio_attr -c adar3000_0 temp16 raw)
   offset=$(iio_attr -c adar3000_0 temp16 offset)
   scale=$(iio_attr -c adar3000_0 temp16 scale)
   echo "raw $raw offset $offset scale $scale"
   awk "BEGIN { printf \"%.1f degC\n\", ($raw + $offset) * $scale / 1000 }"

Expected output; the code and temperature follow the board:

.. code-block:: bash

   raw 124 offset -99.750000 scale 917.431193
   22.2 degC

**2. Direct control bank**

Write, then read back, the delay and attenuation of beam 1, element 1:

.. code-block:: bash

   iio_attr -c -o adar3000_0 phase5 raw 21
   iio_attr -c -o adar3000_0 phase5 raw
   iio_attr -c -o adar3000_0 power5 raw 42
   iio_attr -c -o adar3000_0 power5 raw

Expected output:

.. code-block:: bash

   21
   21
   42
   42

**3. Beam mode**

.. code-block:: bash

   iio_attr -d adar3000_0 beam1_mode
   iio_attr -d adar3000_0 beam1_mode_available

Expected output:

.. code-block:: bash

   direct
   direct memory fifo instant_direct reset mute

**4. RAM sequencer range**

Read the power-on range of beam 1, set it to 10 to 20 and read it back:

.. code-block:: bash

   iio_attr -d adar3000_0 beam1_ram_start
   iio_attr -d adar3000_0 beam1_ram_stop
   iio_attr -d adar3000_0 beam1_ram_start 10
   iio_attr -d adar3000_0 beam1_ram_stop 20
   iio_attr -d adar3000_0 beam1_ram_start
   iio_attr -d adar3000_0 beam1_ram_stop

Expected output:

.. code-block:: bash

   0
   63
   10
   20
   10
   20

**5. Amplifier bias and enable**

The beam amplifiers are named ``EL0H`` to ``EL3H`` and the element amplifiers
``EL0V`` to ``EL3V``. Read the power-on operational state of beam amplifier 0,
then write and read back the sleep state of beam amplifier 2 and of element
amplifier 1:

.. code-block:: bash

   iio_attr -d adar3000_0 amp_bias_operational_EL0H
   iio_attr -d adar3000_0 amp_en_operational_EL0H
   iio_attr -d adar3000_0 amp_bias_sleep_EL2H 5
   iio_attr -d adar3000_0 amp_bias_sleep_EL2H
   iio_attr -d adar3000_0 amp_bias_sleep_EL1V 2
   iio_attr -d adar3000_0 amp_bias_sleep_EL1V
   iio_attr -d adar3000_0 amp_en_sleep_EL1V 0
   iio_attr -d adar3000_0 amp_en_sleep_EL1V

Expected output:

.. code-block:: bash

   3
   1
   5
   5
   2
   2
   0
   0

**6. Update source**

The update, reset and mute commands of the next steps are driven over SPI:

.. code-block:: bash

   iio_attr -d adar3000_0 update_intf_ctrl
   iio_attr -d adar3000_0 update_intf_ctrl_available
   iio_attr -d adar3000_0 update_intf_ctrl SPI

Expected output:

.. code-block:: bash

   pin
   pin SPI
   SPI

**7. Memory load mode**

With beam 2 in memory load mode its channels address RAM beamstate
``beam2_ram_index``. Write a different delay to beamstates 5 and 6 of beam 2,
element 0, and read each back:

.. code-block:: bash

   iio_attr -d adar3000_0 beam2_load_mode memory
   iio_attr -d adar3000_0 beam2_ram_index 5
   iio_attr -c -o adar3000_0 phase8 raw 33
   iio_attr -d adar3000_0 beam2_ram_index 6
   iio_attr -c -o adar3000_0 phase8 raw 44
   iio_attr -d adar3000_0 beam2_ram_index 5
   iio_attr -c -o adar3000_0 phase8 raw
   iio_attr -d adar3000_0 beam2_ram_index 6
   iio_attr -c -o adar3000_0 phase8 raw

Expected output:

.. code-block:: bash

   memory
   5
   33
   6
   44
   5
   33
   6
   44

**8. FIFO, update and reset**

Put beam 3 in FIFO mode and queue two beamstates through its channels; the
eighth value of each, ``power15``, commits it. Then issue an update, which
dequeues one beamstate, and a reset, which empties the queue:

.. code-block:: bash

   iio_attr -d adar3000_0 beam3_mode fifo
   iio_attr -d adar3000_0 beam3_load_mode fifo
   for n in 1 2; do
   	for c in phase12 power12 phase13 power13 phase14 power14 phase15 power15; do
   		iio_attr -c -o adar3000_0 $c raw $n > /dev/null
   	done
   done
   echo "queued:     wr $(iio_attr -d adar3000_0 beam3_fifo_wr) rd $(iio_attr -d adar3000_0 beam3_fifo_rd)"
   iio_attr -d adar3000_0 beam3_update 1
   echo "one update: wr $(iio_attr -d adar3000_0 beam3_fifo_wr) rd $(iio_attr -d adar3000_0 beam3_fifo_rd)"
   iio_attr -d adar3000_0 beam3_mode reset
   iio_attr -d adar3000_0 beam3_update 1
   echo "reset:      wr $(iio_attr -d adar3000_0 beam3_fifo_wr) rd $(iio_attr -d adar3000_0 beam3_fifo_rd)"

Expected output:

.. code-block:: bash

   fifo
   fifo
   queued:     wr 2 rd 0
   0
   one update: wr 2 rd 1
   reset
   0
   reset:      wr 2 rd 2

**9. Instantaneous direct mode guard**

A beam in instantaneous direct mode cannot enter its reset or mute beamstate,
so selecting mute is refused:

.. code-block:: bash

   iio_attr -d adar3000_0 beam3_mode instant_direct
   iio_attr -d adar3000_0 beam3_mode mute; echo "exit $?"

Expected output:

.. code-block:: bash

   instant_direct
   ERROR: Invalid argument (22) while writing 'beam3_mode' with 'mute'
   exit 1

**10. Buffer load into RAM**

The output buffer of the device is loaded into the RAM or the FIFO of the
enabled beams each time its trigger fires. Create a timer trigger and assign
it to the device:

.. code-block:: bash

   mount | grep -q configfs || mount -t configfs none /sys/kernel/config
   mkdir -p /sys/kernel/config/iio/triggers/hrtimer/t0
   echo t0 > /sys/bus/iio/devices/iio:device1/trigger/current_trigger
   cat /sys/bus/iio/devices/iio:device1/trigger/current_trigger

Expected output:

.. code-block:: bash

   t0

Push four beamstates for beam 0 into RAM beamstates 0 to 3, then read them
back through the channels. Scan ``n`` carries the values ``8n`` to ``8n + 7``.
The ``sleep`` keeps the buffer enabled until the trigger has fired:

.. code-block:: bash

   iio_attr -d adar3000_0 beam0_load_mode memory
   iio_attr -d adar3000_0 beam0_ram_index 0
   python3 -c "import sys; sys.stdout.buffer.write(bytes(range(32)))" > beamstates.bin
   (cat beamstates.bin; sleep 1) | iio_writedev -b 4 adar3000_0 \
   	phase0 power0 phase1 power1 phase2 power2 phase3 power3
   echo "iio_writedev exit $?"
   for s in 0 1 2 3; do
   	iio_attr -d adar3000_0 beam0_ram_index $s > /dev/null
   	echo "beamstate $s: $(for c in phase0 power0 phase1 power1 phase2 power2 phase3 power3; do
   		iio_attr -c -o adar3000_0 $c raw; done | tr '\n' ' ')"
   done

Expected output:

.. code-block:: bash

   memory
   0
   WARNING: High-speed mode not enabled
   iio_writedev exit 0
   beamstate 0: 0 1 2 3 4 5 6 7
   beamstate 1: 8 9 10 11 12 13 14 15
   beamstate 2: 16 17 18 19 20 21 22 23
   beamstate 3: 24 25 26 27 28 29 30 31

**11. Register access**

Read the SPI revision register, then write and read back the scratchpad:

.. code-block:: bash

   iio_reg adar3000_0 0x00B
   iio_reg adar3000_0 0x00A 0x5A
   iio_reg adar3000_0 0x00A

Expected output:

.. code-block:: bash

   0x1
   0x5a

Testing
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Creating the setup
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

.. figure:: ../images/adar3000_zcu102_setup.jpg
   :alt: ZCU102 with the SDP-I-FMC interposer and the evaluation board
   :width: 900

   ZCU102 with the SDP-I-FMC interposer on FMC HPC1 and the ADAR3000/3001-EVALZ

.. esd-warning::

Follow the steps in this order, to avoid damaging the components:

#. Get the :xilinx:`ZCU102`.
#. Configure the :xilinx:`ZCU102` for JTAG boot mode (mode switch SW6[4:1] in
   the position **ON,ON,ON,ON**).
#. On the ADAR3000/3001-EVALZ, fit the jumpers on P8 and P9, leave P4 as
   shipped (pin 1 to pin 2), and make sure P2, P12 and P13 are open, see
   :ref:`eval-adar3000 user-guide hardware-configuration`.
#. Connect the SDP-I-FMC interposer to the FPGA carrier FMC **HPC1** socket
   (J4), and the ADAR3000/3001-EVALZ to the interposer's 120-pin SDP
   connector, P5.
#. Connect the bench supplies to the evaluation board test loops, with the
   outputs off, as described in :ref:`eval-adar3000 user-guide power-supply`.
#. Connect USB UART (Micro-USB) to your host PC (J83).
#. Connect USB JTAG (Micro-USB) to your host PC (J2).
#. Plug the power supply into the 12 V power input connector (J52).
#. Turn on the power switch on the FPGA board, then the bench supplies.
#. Make sure the FMC ``VADJ`` rail is at 1.8 V, see
   :ref:`eval-adar3000 user-guide vadj`.
#. Open the UART terminal on the first ttyUSB or COM port the ZCU102
   registers.
#. Build and run the basic example using the steps shown in
   :external+no-OS:doc:`projects/beamformer/adar300x`.
#. Observe the console output messages on your terminal.

.. seealso::

   For more detailed information on ZCU102 switch configuration, check the
   *ZCU102 Hardware User Guide* (chapter "MPSoC Device Configuration")
   `here <https://docs.amd.com/v/u/en-US/ug1182-zcu102-eval-bd>`__.

Using the IIO example
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The IIO example serves the device over the same UART to libiio clients such as
``iio_info``, ``iio_attr`` and ``iio_rwdev``. Build and flash the
``iio_example`` variant, close the UART terminal, and check that the device
enumerates:

.. code-block:: bash

   iio_info -u serial:/dev/ttyUSB0,115200,8n1

The output lists one device, ``adar3000``, with 33 channels and an output
buffer. The complete step by step IIO test procedure, with the expected output
of every step, is in :external+no-OS:doc:`projects/beamformer/adar300x`.
